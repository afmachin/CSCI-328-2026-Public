=== Step 1 - seam ===

  GradeSource, SisGradeSource, and a no-argument constructor that
  delegates. The class had no explicit constructor before, so writing
  that one back by hand is what keeps every caller compiling.

      pass   clean enrolment
      pass   missing prerequisite

      pass   section full

  0 pins broken. Commit.

=== Step 2 - extract, one rule at a time ===

  Five private methods, one per rule. Behaviour unchanged:

      pass   clean enrolment
      pass   missing prerequisite
      pass   over the credit cap
      pass   section full
      pass   two failures at once

  0 pins broken -- but look at what the extraction cost.

      private boolean checkPrerequisites(String[][] rows,
                                         CourseOffering offering,
                                         List<String> errors)

  Each rule has to report two things: that it failed, and why. A boolean
  carries the first. The second had to be passed in as a mutable list for
  the method to write into -- so every extracted rule now takes an
  out-parameter it only ever appends to.

  That parameter is not a wart in the refactoring. It is the design
  telling you that a rule's result is a value nobody modelled, and it is
  the same reason the caller cannot report more than one failure.

=== Step 3 - now change the behaviour ===

  Every rule runs; every reason is kept. This is the feature, and it is
  a separate commit from Steps 1 and 2.

      pass   clean enrolment
      pass   missing prerequisite
      pass   over the credit cap
      pass   section full
      BREAK  two failures at once
             recorded: Dana Vale could not register: / Missing prerequisite: CS101
             now:      Dana Vale could not register: / Missing prerequisite: CS101 / Would total 20 credits, limit is 18

  1 pin broken, and it is the right one.

  Four cases did not move, because a case that fails one rule reports one
  rule whether you return early or collect. Four pins passing was never
  evidence that the change worked -- it was evidence that four of the five
  could not tell. Only the case built to fail twice can see this change,
  which is why Step 0 recorded it.
